# T001.5 — On-demand top-camera illumination

**Status:** Authorized — focused engineering follow-up; physical verification pending.

**Workstream:** [Pick-and-place machine readiness](README.md)

## Goal

Reduce top-camera LED heat and unnecessary on-time. The operator reports the top illumination assembly becoming extremely hot and intermittent top-camera USB disconnects. Heat transfer to the camera is a hypothesis, not a confirmed cause. Switch off and allow cooling before further operation if the assembly is overheating; verify LED current, power supply and thermal ratings independently.

## Scope

- Top/position camera only for this task. Keep bottom-camera illumination behavior and all calibration settings/algorithms unchanged.
- Default the physical top LED OFF at idle, even if the active vision profile requests lighting. Separate saved profile lighting preference (power/RGB/on) from runtime permission to energize the lamp. Preserve saved profiles, camera capture and manual camera navigation.
- Enable the LED only for an active top-camera calibration/vision acquisition that requires light; turn it off immediately after the acquisition/operation no longer needs it, including travel, waiting for operator approval and bottom-camera-only steps. Reuse the existing operation lifecycle and lighting commands rather than adding a new framework. Keep stable illumination during each acquisition and allow exposure settling/fresh frames before accepting observations.
- For intentional manual vision tuning/preview, preserve an explicit bounded illumination action with automatic expiry and immediate OFF. Do not allow passive live camera viewing, profile selection/reselection or property edits to latch the light ON. Future production vision acquisitions will need the same on-demand lifecycle; do not build the production workflow in this task or regress existing active top-camera vision operations.
- Ensure OFF on normal completion, cancellation, validation failure, exception, modal close, idle, and controlled shutdown/disconnect when commands can still reach the controller. Guard against competing operations and stale timers/re-enablement. Investigate controller-side timeout/fail-off capability for loss of host communications or crash; host cleanup alone cannot guarantee physical OFF after a lost connection. Flag this hardware/firmware gap if present rather than claiming fail-safe behavior. No unrelated firmware changes without approval.
- Provide a bounded maximum continuous illumination interval or watchdog for any acquisition/preview, with the limit chosen and documented from actual hardware/operation requirements; a timeout must turn the light off and fail the affected acquisition safely, not leave it lit or repeatedly cycle it. No guessed thermal-safe duty cycle or assumption that software alone fixes excessive heating.
- Inspect existing `Machine.SetVisionProfile` overloads, `IMachine.ConfigureTopLight`, implementation in `Machine.Properties.cs`, direct configuration in `VisionProfileViewModel`, and machine disconnect/shutdown paths. Audit other direct top-light controls, including workbench and manual toggles; ensure none bypass the intended runtime policy in the machine application.

## Verification

- Test idle/profile changes, acquisition start/settle/end, repeated captures, preview expiry, cancel/failure/timeout/close and controlled disconnect. Verify bottom-light behavior and saved profile values are unchanged. Confirm actual controller OFF where feedback is available; distinguish sent command from confirmed state.
- Operator-supervised physical test: observe LED off during idle and non-vision travel, on only when needed for top-camera calibration, then off on completion and abort. Compare camera/LED temperature and USB stability with prior continuous illumination under comparable conditions; stop if overheating recurs. Do not conclude heat caused disconnects from a single successful test.
- Record source commit/PR, focused build/tests, physical evidence and unresolved hardware/controller limitations.

## Dependencies

Can proceed alongside T001 with coordination of overlapping source files. Do not overwrite ongoing T001 shared-camera or Full Diagnostics work. No changes to tool offsets, camera geometry, pickup tolerance, calibration history semantics or machine-side motion algorithms.
