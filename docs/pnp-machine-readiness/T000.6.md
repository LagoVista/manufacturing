# T000.6 — Extend automatic thresholding to additional vision detectors

**Status:** Authorized for engineering; profile-by-profile physical acceptance pending.

**Workstream:** [Pick-and-place machine readiness](README.md). Follow-up to accepted [T000.5](T000.5.md) and [T002](T002.md).

## Goal

Make additional optical calibration and part-localization workflows robust to ordinary changes in ambient light without repeated manual threshold adjustment. Maintain the existing geometry, safety and detector-specific acceptance criteria.

## Current baseline

Known Location already has an opt-in ROI Otsu pipeline and temporal/photometric gates from T000.5. Board Fiducial already uses an opt-in extension of that path from T002 (including polarity handling and smaller foreground occupancy); preserve it rather than implement it again. StagingPlateHole and CalibrationDisc already have specialized Otsu contour detection. Machine Fiducial previously required manual adjustment from 67 to 37 to restore clean segmentation under changed lighting while the top LED was on. Nozzle detection and feeder barcode/white-corner detection have specialized pipelines.

## Scope and priorities

1. Machine Fiducial (macfiducial): first priority. Reuse the existing automatic segmentation machinery with appropriate target polarity, ROI, calibrated physical size and ambiguity checks. Preserve machine-reference calibration semantics and original manual path.
2. Feeder Fiducial (feederfiducial) and tape-hole profiles (tapehole, tapeholewhite, tapeholeblack, tapeholeclear): prioritize to support T006/T007. Validate individually for bright/dark targets and tape materials; do not assume all use the same polarity or occupancy.
3. Staging Plate Hole: review its existing Otsu path and whether effective-threshold display, preview/detector agreement, or robustness needs improvement. Do not add a redundant second threshold or change accepted geometry.
4. Part-in-tape (white/black/clear), Square Part, Part Inspection and Part on Board: audit detector-specific use of threshold and evaluate opt-in adaptation with T007/T008/T009. Implement only where target-specific raw-frame evidence supports it; record deferred cases instead of imposing a circle detector on rectangular/other components.
5. Known Location and Board Fiducial: regression coverage only unless a demonstrated defect warrants a focused fix. Preserve specialized nozzle/nozzle calibration, bottom calibration disc, feeder barcode decoding and white-corner/origin algorithms; any changes to these require separate evidence and review.

## Implementation requirements

- Reuse VisionProfile.AutoThreshold, existing ImageAdjustments controls, ShapeDetectionService, CircleDetector, KnownLocationAutoThresholdGate and applicable rectangle/corner detection infrastructure. Consolidate genuinely shared threshold/ROI/photometric logic where useful; keep target-specific detectors, polarity, expected occupancy, size, contour and temporal gates separate. Avoid a blanket global Otsu switch, double thresholding or duplicate models.
- Make auto mode explicit and opt-in for each supported profile, with manual PrimaryThreshold retained and backward-compatible defaults. Computed threshold remains transient; no silent profile saves. UI only exposes auto mode where implemented; display effective threshold (0–255 and 0–100), mode, actual binary preview consistent with detector input, and rejection/quality status.
- Analyze fresh grayscale ROI before manual thresholding, respect calibrated camera scale and existing masking/blur/invert conventions, reject low contrast, glare/saturation, ambiguous/missing targets and unstable frames. Tune per detector based on actual target data; no universal foreground fraction or copying the Known Location physical diameter/tolerances. Reset history on profile, geometry, mode, or acquisition context change.
- Preserve accepted calibration offsets, machine/board transforms, motion tolerances, camera scale, safety and manual fallback. Coordinate with T001.5 settled illumination, T005–T007 active changes and T008/T009 follow-ons. No automatic changes to exposure, LED power or gain as part of this task; do not regress existing board exposure workflow.
- No machine motion without existing operator-supervised acquisition and safety checks. Implement incrementally and report results per profile; do not block the feeder family while pursuing optional detectors.

## Verification and acceptance

Stationary raw grayscale tests under normal/dim/bright/uneven illumination, contrast/polarity variation, glare, missing or ambiguous targets, manual/automatic switches and profile changes. Record effective thresholds, center/size (or rectangle/angle where relevant), repeatability and false accept/reject behavior against the existing calibrated manual baseline. Confirm no stale frames accepted, no stored geometry/threshold mutation, and no regressions in already accepted Known Location, board, staging, nozzle, disc and barcode paths. Build shared projects and Windows WPF application where available; distinguish synthetic/native/unit/build and physical evidence.

Physically verify Machine Fiducial first, then feeder/tape targets as hardware is available. Record profile-by-profile results and limitations; never infer a passing profile from another detector's success. Retain original physical tolerances and verify existing supervised calibration operations before enabling use. Record source commit, focused test results, raw-frame/physical evidence, and any deferred profile cases.

## Dependencies

T000.5, T001.5 and T002 accepted. Coordinate with T005–T009; this is parallel supporting work, not a requirement to finish every detector before continuing feeders. No publication, deployment, or source implementation from this planning commit.
