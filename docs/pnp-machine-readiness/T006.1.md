# T006.1 — Workbench feeder discovery and registration

**Status:** Planned — awaiting coordination/implementation handoff.

**Workstream:** [Pick-and-place machine readiness](README.md)

## Goal

Make the Automatic Feeder Workbench the single intuitive place to discover, register and select installed automatic feeders. Eliminate the need to switch between Diagnostics and Configuration to register newly discovered hardware.

## Scope

- Extend the existing left-hand feeder list to show configured feeders and unregistered feeders responding in the latest Photon discovery scan. Order by physical slot; distinguish registered and unregistered records visually.
- Match configured and discovered feeders using both slot and case-insensitive UUID. Preserve the existing discovered, no response, communication error, mismatch, moved and not-scanned distinctions. No response does not establish physical absence.
- Allow selection of an unregistered discovered feeder and show its discovered slot and UUID. Provide a clear Register Feeder action in the workbench, with existing template selection, name and optional component assignment. Prepopulate the slot and UUID from discovery; use the existing template factory, models and feeder save API. Do not introduce a second registration mechanism.
- Validate the current machine, unique rail assignment and latest discovery identity before registration. Recheck live identity for registration (not optical navigation). Reject conflicting slot/UUID assignments; report moved or mismatched existing feeders explicitly rather than silently creating duplicates or reassigning them.
- On successful registration, refresh the list, select the newly registered feeder and allow the existing landmark calibration workflow immediately. On failure, preserve the discovered entry and entered information and show actionable feedback.
- Keep discovery/registration independent of calibration and tape movement. No automatic movement, feed, inventory decrement or calibration on selection or registration. Retain the existing manual diagnostics panel and motion safeguards.

## Completion criteria

Demonstrate discovery of one previously configured and one new feeder, registration of the new feeder entirely within the workbench, and immediate selection for calibration. Verify duplicate/moved/mismatched identity handling, partial or failed scans, refresh and failure behavior, and that no unintended motion occurs. Provide focused tests and local WPF/physical evidence.

## Dependencies

T005 discovery/identity infrastructure and T006 workbench. May be picked up independently of T007; not a blocker for ongoing physical landmark and pickup calibration.

Record source commit or PR, tests, operator evidence, outstanding blockers and next step. Planning only; implementation requires an agreed handoff.
