# T000.5 — Automatic vision threshold tuning

**Status:** Accepted and closed — Known Location pilot; operator reports satisfactory on-machine operation.

**Workstream:** [Pick-and-place machine readiness](README.md)

## Problem

The top-camera Known Location calibration disc is sensitive to ambient lighting. On November 27 the operator showed a noisy, fragmented white target at manual PrimaryThreshold 42 and a clean, filled circular target at 32 after a change in room lighting. The objective is stable optical localization without manually tuning threshold each session. These are processed screenshots, not raw grayscale regression frames; no accuracy claim from appearance alone.

## Scope

- Begin with the top-camera Known Location bright circular calibration target. Reuse the existing vision pipeline, camera/profile scale, circle tracking and KnownLocationCylinderCenteringRunner. Inspect CircleDetector and ShapeDetectionService: staging-hole and bottom CalibrationDisc already use Otsu/contour segmentation; Known Location currently uses legacy circle detection and manual preprocessing.
- Add a profile-selectable Auto Threshold option with manual threshold retained as an explicit fallback. Preserve existing saved profiles and their settings; enable automatic mode for Known Location as an operator-selectable trial, not a blanket change to all profiles. Use a backward-compatible typed setting if persistence is needed. Keep existing specialized bottom-disc, nozzle, feeder barcode and white-corner detection behavior unchanged.
- Compute threshold from fresh grayscale target-region data (before manual binarization), with existing calibrated search ROI and appropriate smoothing. Start with existing Otsu approach; compare alternatives only if actual raw frames show it is inadequate. Avoid a global histogram dominated by unrelated background or highlights. Reject insufficient foreground/background separation, ambiguous target or saturated frames. Do not select a threshold just because a circle appears.
- Keep actual binary preview and detector input consistent; display the effective threshold in both raw 0–255 and existing 0–100 UI units, automatic/manual state, and detection confidence/rejection evidence. Keep the computed threshold transient; do not silently rewrite PrimaryThreshold or save profiles. Manual override remains available.
- Require existing diameter/position bounds, fresh stabilized observations and safe motion checks. Check threshold and center stability across frames; if lighting changes during acquisition, reacquire instead of using stale detections. Preserve geometry, scale, tolerances, stored offsets and all existing motion/recovery safeguards. No autonomous exposure/gain/LED tuning in this task.
- Coordinate with T001 and T001.5: illumination must settle before analyzing fresh frames; avoid changing lamp state during acquisition. Do not overwrite parallel changes.

## Tests and acceptance

- Focused tests on raw grayscale synthetic and real captured frames where available: brightness/contrast changes, uneven lighting, noise, glare, missing/ambiguous targets and manual override. Demonstrate stable center and diameter under varied lighting, not merely visually clean masks. Use existing physical accuracy/tolerance gates; do not relax them.
- Physical check: hold the disc and camera pose fixed, vary room illumination within normal operating range, compare automatic threshold, detected center and diameter against the manual reference, then exercise supervised Known Location acquisition. Record effective threshold and residuals; confirm no unwanted persisted settings changes. Obtain raw grayscale frames from the machine if needed; the operator's two processed screenshots alone cannot establish Otsu performance.
- Review source commit/PR, focused build/tests, physical results and limitations. Expand to other profiles only after reviewing this pilot; do not globally alter barcode, fiducial, staging or part inspection behavior.
