# T006 — Auto feeder placement calibration

**Status:** Implementation authorized; physical acceptance pending.

**Workstream:** [Pick-and-place machine readiness](README.md)

## Goal

Establish the physical installed location of an automatic feeder in machine coordinates.

## Scope

Reuse machine/staging plate reference geometry and existing calibration operation patterns where appropriate. Determine the actual feeder reference using the position camera or agreed physical reference; capture the verified offset with correct feeder identity and explicit persistence.

## Completion criteria

Re-select/reload the feeder and return to its reference repeatably; verify placement independently of pocket/part offsets; retain previous calibration on failed runs.

## Dependencies

T001, T005; T004 if relevant.

## Review / handoff

Record source commit or PR, focused test results, physical verification (if applicable), remaining blockers and next step. Engineering completion is not proof of on-machine acceptance. Keep changes limited to this task and follow the coordination plan.

Use the rail's configured SlotWidth, exclusive slot range and existing 0/180 degree rail convention; existing fiducial/pick offsets remain machine-relative. Select a saved feeder, unlock settings, confirm clearance, run Calibrate Feeder Placement, and explicitly Save the verified candidate. Check live Photon UUID before/after measurement and before saving; no feed, pick or inventory movement. Reload and Go To Fiducial for independent verification. Calibration failure or cancellation by context change does not overwrite the prior fiducial. Existing rail geometry assumptions need physical verification on both rail orientations. T007 owns pickup offset and presence.

Feeder-fiducial detection now requires one eligible physical circle (concentric edges may represent one target), consecutive frames, and position stability using the existing board geometry gate. The feeder uses its existing Hough profile; auto-threshold expansion to this profile is not included in T006.

## Operator UI refinement

Dedicated Auto Feeder Calibration modal follows the existing strip-feeder calibration window. Select one saved feeder from the machine list, confirm clearance, explicitly Run Calibration, inspect persistent progress/identity mismatch, then Save Placement. Save retains selection for Go To Fiducial. Closing discards an unsaved candidate and never cancels queued motion; cannot close during active operation. Future batch and current-job filters will supply a list of targets to the same single-feeder procedure, not introduce a second calibration algorithm. Larger white instructions/status. No automatic UUID reassignment on mismatch.

## Three-dot landmark — shared model first

The fixed Photon feeder PCB has three exposed copper circles, with a larger center circle. It is distinct from tape sprocket holes. The rail's calibrated FirstFeederOrigin (left-edge reference), slot pitch and slot index give the coarse location; the existing feeder FiducialOffset and PickOffset remain independent. Add the selectable shared profile `feederlandmark` (Feeder Landmark (3 Dots)), plus nullable physical center-dot diameter, side-dot diameter and center-to-side spacing in mm. No guessed measurements or new persisted defaults. The original `feederfiducial` and `custom` catalog entries are corrected without migrating or renaming saved profiles. Existing machine PUT /api/mfg/machine persists camera VisionProfiles; deploy the updated shared manufacturing model with the cloud host before storing new fields. This cut only establishes the shared model and catalog; the detector, marker measurements, full-screen workbench and physical validation are subsequent work. Existing single-circle procedure is not switched to this new key until the three-dot detector is implemented.

### Routine navigation usability correction

The workbench no longer requires a clearance checkbox for explicit Go To or camera preview. Each operation waits up to five seconds for transient machine/transport activity to settle before dispatch, and reports busy flag, queue count and unacknowledged bytes on timeout. Existing live UUID, homing, origin calibration, Manual mode, vacuum, safe-height, bounds, context and controller motion-completion checks remain. No automatic motion retries, no change to T005 tape-movement arming, and no offset writes. Dedicated automated landmark procedure remains pending. Source-only change; no separate build requested.

### Optical navigation independent of Photon communications

Explicit operator camera navigation to rail reference, slot origin, calculated landmark and pickup no longer issues a Photon GetId request. Optical placement measurement stages a candidate without interrogating the feeder. Machine idle, no concurrent bus operation, saved configuration context, homing, safe Z, bounds and optical verification remain required. The existing placement save retains live UUID verification before writing a feeder-specific offset; tape initialization/advance/retract retain all existing identity and transport checks. No change to rail geometry, stored offsets or production behavior. The new three-dot detector is still pending. Source-only follow-up; no special build requested.

### Dedicated three-dot optical detector and first-slot rail reference

Feeder Landmark selects full-frame bright-contour segmentation with automatic Otsu or manual threshold. A unique near-collinear symmetric triplet with a larger middle disk is required; only its middle centroid enters existing consecutive-frame stability and bounded corrections. Physical dimensions are optional; initial relative thresholds need live validation. Workbench Calibrate Landmark stages a candidate; settings must be unlocked, no clearance checkbox or RS485 for acquisition. For the first slot of its rail only, Save Rail Reference proposes measured center minus existing nominal fiducial offset, writes FirstFeederOrigin via existing machine save, and consumes the candidate. Save Feeder Offset instead writes the individual feeder offset after live UUID verification. These are mutually exclusive choices; never apply both. Rail-wide shift assumes the existing offset is a trustworthy nominal reference; no slot renumbering, pitch changes, rotation changes or pickup offset writes. WPF and physical acceptance remain pending.
