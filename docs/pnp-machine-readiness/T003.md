## Goal

## Scope

Add a print-friendly action for the selected feeder, supporting the existing orientation and white-cut corner convention. Ensure physical dimensions are preserved at actual-size printing.

## Implementation handoff — November 27

Primary implementation repository: `softwarelogistics/ui-manufacturing`. Inspect the current feeder list/detail and machine strip-feeder editor; reuse the generated contracts and existing authenticated Manufacturing service. Keep changes independent of T001 and machine-side calibration.

- Add a Print Feeder Label action for an existing selected strip feeder. Use the authoritative persisted `FeederId` (four hexadecimal digits, including leading zeros); blank/invalid IDs must not produce a production label. Do not invent an ID from a database GUID, generate a random ID or silently write feeder settings. If assignment is not already supported in the UI, identify the gap for review.
- Render the calibrated 11-bar marker, not the legacy prototype: START 2.50 mm; eight data symbols from the 16-bit ID, MSB-first; four-level widths 0.50, 0.75, 1.00, 1.25 mm; one CRC-2 check symbol (polynomial x²+x+1, initial register 3, no reflection/final XOR); END 0.25 mm. Match the existing C# decoder and tests, including gap and quiet-zone geometry. The reference 0x1B1B decodes symbols 0,1,2,3,0,1,2,3 and check symbol 1; do not use that ID for all production labels.
- Use vector output with physical millimeter dimensions and a print-only actual-size layout; retain the current nominal 20 x 2 mm marker format. Confirm the complete symbol sequence fits with required gaps and white margins before finalizing layout; do not silently squeeze bars to fit. Preserve the separate white cut corner and black START reference, and the vertical top-left/top-to-bottom and horizontal bottom-left/left-to-right conventions. Use existing decoder/source as authority and flag any contradictory legacy prototype notes rather than changing machine geometry.
- Provide a clear preview, feeder identifier and print instructions (100% / actual size, no fit-to-page; keep any human-readable text outside the optical marker). Prefer the existing Angular UI and browser print workflow; no new printer integration or machine-side changes unless explicitly approved.
- Test encoding (leading zeros, boundary IDs, 0x1B1B CRC reference, invalid/blank input), physical bar/gap geometry and both orientations. Use existing generated contracts, zoneless-compatible Angular code, and normal build/test flow. Report any needed API/model changes before expanding scope.

## Accepted batch-label design — November 27

The design review replaces the original single-feeder print action with a dedicated **Feeder Labels** screen as the primary workflow. Optional individual-print shortcuts may reuse that screen; they are not required for initial delivery.

- In the existing manual/strip-feeder editor, expose the persisted four-hex-character FeederId and an explicit Assign ID action. Allocate an unused ID, normalize uppercase, preserve leading zeros, and enforce organization-scoped uniqueness using existing authorized persistence. Never silently assign or change an ID during printing. Reprints retain the saved identity. Verify existing service/contracts and uniqueness support; if server changes are necessary, keep them minimal and report them.
- The Feeder Labels screen lists manual strip feeders (including attached feeders), with name, saved ID, orientation, search/filter, checkboxes, select all eligible and selected count. Missing, malformed or conflicting IDs are not printable. Generate a preview from saved records only; paginate selections across physical labels.
- Target Phomemo M120, nominal 203 DPI, approximately 30 x 50 mm adhesive stock. Default stock dimensions 30 x 50 mm, configurable to match measured stock. Start with six markers per physical label, subject to actual printable area; use normal Windows driver/browser actual-size printing, not a printer-specific integration.
- Use black-on-white vector markers with unchanged calibrated bar widths and CRC-2, 0.50 mm gaps and at least 2 mm leading/trailing white space from the decoder test fixture. A provisional 24 x 2 mm retained strip supersedes the earlier nominal 20 x 2 mm target; verify all IDs fit without scaling, and verify physical fit and existing scan travel on the machine before accepting the length. Do not change the machine decoder, scan or calibration to accommodate printing.
- Print crop/cut guides in discarded material, aligned to both edges of the optical corner, never leaving dark guide marks on the retained white corner or interfering with barcode bars/quiet zones. Human-readable IDs remain outside the retained optical strip. A horizontal bottom-left origin marker may be rotated clockwise 90 degrees for a vertical top-left origin; preserve the start-to-end reading direction. Show application orientation in preview/instructions.
- Add a clearly identified non-production test-label action for reference 1B1B, with a measurable scale reference outside the optical strip. Print at 100%, check physical dimensions and darkness, cut/apply and verify white-corner detection and complete 11-bar CRC-2 scan against the saved production ID. Verify representative short/long encodings, both orientations, eligibility, duplicate rejection, pagination and crop-guide isolation. Physical verification remains separate from engineering closure.
